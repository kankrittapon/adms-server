# แผน Flow งานบัญชีพล + รองรับระบบการลา / ไปราชการ / ช่วยราชการ

สถานะ (2026-10-05): **ทำครบทุกระยะและ deploy แล้ว** — ตอนนี้อยู่ใน **โหมดทดลอง** (ลงนิ้วแล้ว 4/84) ระบบจะเริ่มนับจริงเองเมื่อลงนิ้วครบ

## 1. แยกงานออกเป็น 4 เรื่อง ไม่ปนกัน

| งาน | ใครทำ | ที่ไหนในระบบ | ข้อมูลที่เปลี่ยน |
|---|---|---|---|
| **A. สแกนนิ้วเข้า-ออกงาน** (ทุกวัน) | กำลังพลทุกคน ยกเว้นคนที่ "ยกเว้นสแกน" | เครื่องสแกน → เมนู *เวลาเข้า-ออกงาน* | `attendance_logs` เท่านั้น |
| **B. ลงทะเบียนลายนิ้วมือ** (ครั้งเดียวต่อคน) | ENROLLMENT_OPERATOR / ADMIN | เมนู *ลายนิ้วมือ* หรือปุ่ม "ลงทะเบียนลายนิ้วมือ" ในหน้าคน | บัญชีในเครื่อง, enrollment, mapping |
| **C. อัปเดตรายชื่อ / ยศ จาก Excel** | ADMIN | *บัญชีพล* → "อัปเดตรายชื่อ / ยศ จาก Excel" | ข้อมูลใน `human_employees` เท่านั้น (ไม่แตะเครื่องสแกน) |
| **D. เข้า / ออก / ย้ายหน่วย** | ADMIN | *บัญชีพล* → หน้ารายคน | ดูข้อ 2 |

หลักการ: งาน C **ไม่เคย** แตะเครื่องสแกน และงาน B **ไม่เคย** แก้ชื่อหรือยศ การเปลี่ยนยศจึงทำผ่าน Excel ได้เลยโดยไม่ต้องลงนิ้วใหม่
(ส่วนชื่อที่แสดงบนเครื่องสแกน ระบบจะอัปเดตให้ตอนลงนิ้วครั้งถัดไป)

## 2. วงจรชีวิตกำลังพล (งาน D)

```
             ┌─────────── รับเข้าใหม่ ───────────┐
             │ 1. เพิ่มชื่อ (ฟอร์ม หรือ Excel)      │
             │ 2. ต้องสแกนนิ้วไหม?                │
             │    ├─ ต้อง → ลงทะเบียนลายนิ้วมือ (B)  │
             │    └─ ไม่ต้อง (สนง.ผบ., การเงิน)    │
             │         → ตั้ง "ยกเว้นสแกน" + เหตุผล │
             └───────────────┬─────────────────┘
                             ▼
                    ประจำหน่วย (active)
         ┌────────┬──────────┼─────────────┬──────────┐
         ▼        ▼          ▼             ▼          ▼
        ลา    ไปราชการ   ไปช่วยราชการ    เปลี่ยนยศ   ย้ายออก/พ้นหน่วย
     (ระยะ 4)  (ระยะ 4)  (ระยะ 4)       (Excel, C)  (ปุ่ม "ย้ายออก")
     ยังเป็นกำลังพลของหน่วย ไม่ลบนิ้ว                       │
                                                         ▼
                              1. ปิดชื่อ (inactive) — ประวัติเข้างานยังอยู่
                              2. ปิด mapping เพื่อไม่ให้สแกนหลังจากนี้ถูกนับเป็นของคนนี้
                              3. ลบบัญชี + ลายนิ้วมือออกจากเครื่องสแกน
                                 (ถ้าเครื่องไม่ตอบสนอง → ขึ้นในตัวกรอง
                                  "ย้ายออกแล้ว แต่ยังมีนิ้วในเครื่อง" ให้กดลบซ้ำ)
                                                         │
                                       กลับเข้าหน่วยใหม่ → เปิดชื่อ + ลงนิ้วใหม่เสมอ
```

**ข้อตัดสินใจ:** "ย้ายออก" ใช้วิธีปิดชื่อ (inactive) **ไม่ลบแถวข้อมูล** เพราะประวัติการเข้างานและเอกสารลาเดิมต้องอ้างถึงคนนี้ได้
ส่วนข้อมูลบนเครื่องสแกน (บัญชีและลายนิ้วมือ) จะถูกลบจริง

**ไปช่วยราชการ ≠ ย้ายออก:** คนที่ไปช่วยราชการยังเป็นกำลังพลของหน่วย จึงไม่ลบนิ้ว แค่ไม่นับเป็นขาดในช่วงวันที่ตามคำสั่ง

## 3. นโยบายที่ใช้จริง (ตัดสินใจแล้ว)

| เรื่อง | ข้อตัดสินใจ |
|---|---|
| การแก้ไขข้อมูล | แก้ได้ตลอดเวลา รวมถึงลงลายนิ้วมือ — ยกเลิกช่วงเปิดแก้ไข (`API_WORK_SESSION_REQUIRED=false`) สิทธิ์ยังตาม role และทุกการแก้ไขบันทึก audit |
| ช่วงสแกนเข้างาน | นับเฉพาะ **06:30–11:00** · หลัง **10:00** = มาสาย · สแกนนอกช่วงเก็บไว้แต่ไม่นับ |
| การลา | **บันทึกอย่างเดียว ไม่มีอนุมัติ** (ผบ.พัน ลงนามในเอกสารแล้ว) · บันทึกได้ OPERATOR/ADMIN · ย้อนหลังได้ |
| ยกเว้นสแกน | ถาวร ไม่มีวันหมด: **การเงิน (บางคน)** และ **สำนักงานผู้บังคับบัญชา** · ตั้งรายคนท้ายรายชื่อ หรือเลือกหลายคนพร้อมกัน |
| ไปราชการ / ช่วยราชการ | ไม่ใช่ข้อยกเว้น — บันทึกในเมนู "ลา / ราชการ" ตามช่วงวันที่ในคำสั่ง นับเป็น "ราชการ" ไม่นับขาด |
| พลทหาร | ไม่อยู่ในบัญชีพลและการสแกน (`production_scope=false`) — ซ่อนไว้ ไม่ลบ |
| คนที่ยังไม่ลงนิ้ว | ไม่นับ มา/สาย/ขาด (`NOT_ENROLLED`) · เริ่มนับวันถัดจากวันที่ลงนิ้วเสร็จ |
| เริ่มนับจริง (go-live) | `auto`: เริ่มเมื่อคนที่ต้องสแกนลงนิ้วครบ 100% (ไม่รวมผู้ยกเว้น, ผู้ไปราชการ/ช่วยราชการ, พลทหาร) · ADMIN บังคับเปิด/ปิดได้ที่หน้าระบบ |
| รายงาน Telegram | จ.–ศ. 11:05 · **เฉพาะรายชื่อผู้ขาด** แยกแผนก · ไม่ส่งวันหยุด · **ไม่ส่งก่อน go-live** |

## 4. สถานะรายวัน (คำนวณขณะอ่าน ไม่เก็บลง DB)

ไล่ทีละข้อ ข้อแรกที่ตรงคือสถานะ:

1. มีรายการลา/ราชการครอบวันนั้น → `LEAVE` / `DUTY`
2. ยกเว้นสแกน → `EXEMPT`
3. ยังไม่ลงนิ้ว (หรือยังไม่ถึงวันเริ่มนับ) → `NOT_ENROLLED` (วันหยุด = `OFF`)
4. มีสแกนในช่วง 06:30–11:00 → `PRESENT` / `LATE` (หลัง 10:00)
5. วันหยุด (เสาร์–อาทิตย์ / วันหยุดราชการ) → `OFF`
6. ก่อน 11:00 ของวันนี้ หรือวันในอนาคต → `NOT_YET`
7. ไม่ตรงข้อใด → `ABSENT` (ก่อน go-live แสดงเป็น "ขาด (ทดลอง)")

## 6. ขั้นตอนใช้งานจริง

1. **ลงลายนิ้วมือให้ครบ** — หน้าบัญชีพล → ตาราง "ความพร้อมลงลายนิ้วมือ" → กดแผนก → เลือกคน → "ลงทะเบียนลายนิ้วมือ"
2. **ตั้งยกเว้นสแกน** ให้การเงิน (เฉพาะคน) และสำนักงานผู้บังคับบัญชา
3. **บันทึกผู้ไปราชการ / ช่วยราชการ** ในเมนู "ลา / ราชการ" (คนกลุ่มนี้จะไม่ถูกนับว่ายังขาดลายนิ้วมือระหว่างไป)
4. เมื่อความพร้อมถึง 100% ระบบเริ่มนับจริงและส่ง Telegram ให้อัตโนมัติวันทำการถัดไป
