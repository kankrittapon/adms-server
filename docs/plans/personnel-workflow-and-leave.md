# แผน Flow งานบัญชีพล + รองรับระบบการลา / ไปราชการ / ช่วยราชการ

สถานะ: ร่างแผน (2026-10-02) — ระยะ 1–3 ทำแล้วใน working tree, ระยะ 4–5 ยังเป็นแผน

## 1. แยกงานออกเป็น 4 เรื่อง ไม่ปนกัน

| งาน | ใครทำ | ที่ไหนในระบบ | ข้อมูลที่เปลี่ยน |
|---|---|---|---|
| **A. สแกนนิ้วเข้า-ออกงาน** (ทุกวัน) | กำลังพลทุกคน ยกเว้นคนที่ "ยกเว้นสแกน" | เครื่องสแกน → เมนู *เวลาเข้า-ออกงาน* | `attendance_logs` เท่านั้น |
| **B. ลงทะเบียนลายนิ้วมือ** (ครั้งเดียวต่อคน) | ENROLLMENT_OPERATOR / ADMIN | เมนู *ลายนิ้วมือ* หรือปุ่ม "ลงทะเบียนลายนิ้วมือ" ในหน้าคน | บัญชีในเครื่อง, enrollment, mapping |
| **C. อัปเดตรายชื่อ / ยศ จาก Excel** | ADMIN | *บัญชีพล* → "อัปเดตรายชื่อ / ยศ จาก Excel" | ข้อมูลใน `human_employees` เท่านั้น (ไม่แตะเครื่องสแกน) |
| **D. เข้า / ออก / ย้ายหน่วย** | ADMIN | *บัญชีพล* → หน้ารายคน | ดูข้อ 2 |

หลักการ: งาน C **ไม่เคย** แตะเครื่องสแกน และงาน B **ไม่เคย** แก้ชื่อหรือยศ การเปลี่ยนยศจึงทำผ่าน Excel ได้เลยโดยไม่ต้องลงนิ้วใหม่
(ส่วนชื่อที่แสดงบนเครื่องสแกน ระบบจะอัปเดตให้ตอนลงนิ้วครั้งถัดไป)

## 2. วงจรชีวิตกำลังพล (งาน D)

```
             ┌─────────── รับเข้าใหม่ ───────────┐
             │ 1. เพิ่มชื่อ (ฟอร์ม หรือ Excel)      │
             │ 2. ต้องสแกนนิ้วไหม?                │
             │    ├─ ต้อง → ลงทะเบียนลายนิ้วมือ (B)  │
             │    └─ ไม่ต้อง (สนง.ผบ., การเงิน)    │
             │         → ตั้ง "ยกเว้นสแกน" + เหตุผล │
             └───────────────┬─────────────────┘
                             ▼
                    ประจำหน่วย (active)
         ┌────────┬──────────┼─────────────┬──────────┐
         ▼        ▼          ▼             ▼          ▼
        ลา    ไปราชการ   ไปช่วยราชการ    เปลี่ยนยศ   ย้ายออก/พ้นหน่วย
     (ระยะ 4)  (ระยะ 4)  (ระยะ 4)       (Excel, C)  (ปุ่ม "ย้ายออก")
     ยังเป็นกำลังพลของหน่วย ไม่ลบนิ้ว                       │
                                                         ▼
                              1. ปิดชื่อ (inactive) — ประวัติเข้างานยังอยู่
                              2. ปิด mapping เพื่อไม่ให้สแกนหลังจากนี้ถูกนับเป็นของคนนี้
                              3. ลบบัญชี + ลายนิ้วมือออกจากเครื่องสแกน
                                 (ถ้าเครื่องไม่ตอบสนอง → ขึ้นในตัวกรอง
                                  "ย้ายออกแล้ว แต่ยังมีนิ้วในเครื่อง" ให้กดลบซ้ำ)
                                                         │
                                       กลับเข้าหน่วยใหม่ → เปิดชื่อ + ลงนิ้วใหม่เสมอ
```

**ข้อตัดสินใจ:** "ย้ายออก" ใช้วิธีปิดชื่อ (inactive) **ไม่ลบแถวข้อมูล** เพราะประวัติการเข้างานและเอกสารลาเดิมต้องอ้างถึงคนนี้ได้
ส่วนข้อมูลบนเครื่องสแกน (บัญชีและลายนิ้วมือ) จะถูกลบจริง

**ไปช่วยราชการ ≠ ย้ายออก:** คนที่ไปช่วยราชการยังเป็นกำลังพลของหน่วย จึงไม่ลบนิ้ว แค่ไม่นับเป็นขาดในช่วงวันที่ตามคำสั่ง

## 3. สิ่งที่ทำแล้ว (ระยะ 1–3)

- **Scheduler** — เดิม script ดึง token ไม่ได้ (เรียก `json.load(stdin)` สองครั้ง) จึงล้มทุกวันตั้งแต่ 23 ก.ย. แก้ให้ login ใหม่ทุกครั้งด้วย `jq`
  ให้ window ปิดตรง `end_time`, บันทึก `last_run` และให้หน้า System แจ้งเตือนเมื่อตัวตั้งเวลาไม่ได้ติดต่อ API มาเกิน 3 วัน
- **Migration 015** — เพิ่ม `scan_exempt` และ `scan_exempt_reason`
- **API**
  - `GET /humans?scan_status=needs_enrollment|enrolled|exempt|left_with_account`
  - `GET /humans/summary`
  - `GET /humans/{id}/terminal-accounts`
  - `PATCH /humans/{id}` รับ `scan_exempt` เพิ่ม
- **เมนู** จัดกลุ่มใหม่เป็น 4 กลุ่ม: เวลาเข้า-ออกงาน / บัญชีพล / ลายนิ้วมือ / ผู้ดูแลระบบ
  และทุกหน้ามีแบนเนอร์บอกว่าตอนนี้เปิดหรือปิดการแก้ไขข้อมูล
- **บัญชีพล** มีตัวเลขสรุปที่กดเป็นตัวกรองได้, การ์ดงาน 4 แบบ, คอลัมน์สถานะลายนิ้วมือ
  ส่วนหน้ารายคนมีการตั้งค่ายกเว้นสแกน, ปุ่ม "ย้ายออก" ที่ปิดชื่อและลบนิ้วในขั้นตอนเดียว, และปุ่มลงทะเบียนลายนิ้วมือ
- **ลงทะเบียนลายนิ้วมือ** ลดจาก 6 ขั้นที่ต้องกดเอง เหลือ 4 ขั้นที่มองเห็น
  - สร้างบัญชีในเครื่องให้อัตโนมัติ (ถ้ามีชื่อภาษาอังกฤษ)
  - หลังลงนิ้วเสร็จ ระบบเปิด window สแกนทดสอบเอง
  - เมื่อสแกนทดสอบแล้ว ระบบยืนยันให้อัตโนมัติ
  - ADMIN ยืนยันตัวบุคคลได้ในหน้าเดียวกัน ไม่ต้องไปหน้า Mappings
  - รายชื่อให้เลือกมีเฉพาะคนที่ยังไม่ได้ลงนิ้ว

## 4. ระยะ 4 — ลา / ไปราชการ / ไปช่วยราชการ (ยังไม่ทำ)

### Schema (migration 016)

```sql
absence_types (
  code TEXT PRIMARY KEY,          -- SICK, PERSONAL, VACATION, MATERNITY, OFFICIAL_DUTY, SECONDMENT, TRAINING
  name_th TEXT NOT NULL,
```

### สถานะรายวัน (คำนวณขณะอ่าน ไม่เก็บลง DB)

ไล่เงื่อนไขทีละข้อ ข้อแรกที่ตรงคือสถานะของวันนั้น

1. ไม่ active ในวันนั้น → ไม่นับ
2. วันหยุด / เสาร์อาทิตย์ → `HOLIDAY`
3. มี `absence_records` ครอบวันนั้น → `LEAVE:<type>` หรือ `DUTY:<type>`
   (ถ้าเป็นครึ่งวันและมีสแกนด้วย ให้แสดงทั้งสองอย่าง)
4. `scan_exempt` → `EXEMPT` (ไม่นับขาด)
5. มีสแกน → `PRESENT` หรือ `LATE` (เกณฑ์เวลาเก็บใน `system_configurations`)
6. ไม่ตรงข้อใดเลย → `ABSENT`

### API

- `GET/POST /api/v1/absences`, `POST /api/v1/absences/{id}/cancel`
- `POST /api/v1/absences/import` สำหรับนำเข้า CSV จากหนังสือคำสั่ง ใช้ preview/commit แบบเดียวกับ CSV บัญชีพล
- `GET /api/v1/attendance/daily?date=` ให้ยอดกำลังพลประจำวัน แยกตามแผนก (`branch`)
- `GET /api/v1/attendance/monthly?month=&employee_id=`

## 6. คำถามที่ต้องให้หน่วยตัดสินใจก่อนเริ่มระยะ 4

1. ต้องมี workflow **ขออนุมัติ** ในระบบหรือไม่ — แผนนี้สมมติว่าบันทึกตามเอกสารที่อนุมัติแล้วเท่านั้น
2. **เกณฑ์มาสาย**: กี่โมง และใช้เกณฑ์เดียวทั้งหน่วยหรือแยกตามแผนก
3. ใครเป็นผู้บันทึกการลา: ธุรการของแต่ละแผนก หรือส่วนกลางที่เดียว
4. ประเภทการลาที่ใช้จริงมีอะไรบ้าง และต้องนับโควตาไหม
